01 — the instrument

Most tools separate the visual from the sonic
from the logical. VEKTRA refuses that.

VEKTRA is a node-based environment. Every signal — a sample, a pixel, a number, a vector — is a node. Every connection between them is a wire. Every wire carries time.

You build instruments by writing patches. Patches are documents. They are text, they are inspectable, they are diffable, they are forkable. The system is the source code. The source code is the instrument.

When a wire is connected, the runtime re-evaluates. You do not compile. You do not render. You change a number and the room changes with it.

// runtime

The compiler is a hot-reload daemon. The compiler is also the audio thread. The compiler is also the renderer. They are the same process.

  • 01.Patches are plain text. Version-controllable. Diff-able.
  • 02.Every node is inspectable at runtime. Hover, see the buffer.
  • 03.The audio thread and the render thread share a clock.
02 — how it works

Three commitments. No exceptions.

I.

A graph, not a stack.

Audio nodes, GPU shaders, OSC inputs, MIDI streams, and JavaScript expressions live in the same graph. There is no "audio layer" or "video layer." There are nodes and wires.

// no bridge code
II.

Time is explicit.

Every node declares its temporal mode: trigger, sample, block, scheduled. The scheduler is part of the language. A 1-bar loop is a different thing from a 1ms envelope, and the compiler knows.

// scheduler.open()
III.

Live, forkable, inspectable.

Every running patch is a server. Connect a second laptop and you are in the same session. Fork the patch, branch the timeline, merge the buffers. The instrument is a wiki.

// $ vektra fork
