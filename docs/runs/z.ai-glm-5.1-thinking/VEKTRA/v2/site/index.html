01 — What it is

A way of thinking about time, signal, and form simultaneously.

VEKTRA is not a DAW. It is not a creative suite. It is not a plugin. It is closer to a language — one where frequency drives visual parameters, where gesture rewrites a patch, where time is explicit and nothing is hidden.

Most creative tools separate the visual from the sonic from the logical. VEKTRA treats them as one graph. Every connection is visible. Every parameter is a node. Every moment is addressable.

patch.vk 
let osc = Vek.osc("sine", 220)
let shape = Vek.morph(osc, "ring")
let field = Vek.field(shape, {
  resolution: 64,
  decay: 0.92,
  color: accent
})
Vek.render(field, "viewport")
02 — How it works

Three principles.

01

The unified graph

Audio signals, visual parameters, and logic branches share the same node space. A change at any point propagates through the entire system. No bridges. No export steps. One topology.

02

Live state

Every value is inspectable at every moment. Pause time, fork a signal branch, reroute a connection while the system runs. The patch is not a file — it is a living process.

03

Temporal precision

Time is not hidden behind a timeline scrubber. It is a first-class dimension — sample-addressable, schedulable, mutable. Micro-timing is not an advanced feature. It is the default.

03 — Who uses it

Built for people who make things that behave.

The composer

Elena Voss, Berlin

Elena writes granular synthesis patches that restructure themselves based on audience position. She uses VEKTRA because no other environment lets her route sensor data into spectral parameters without leaving the signal graph.

The installation artist

Marcus Teo, London

Marcus builds room-scale reactive environments where sound and light respond to movement. VEKTRA's unified graph means his Kinect data, audio engine, and projection mapping share one live topology — not three separate systems duct-taped together.

The developer-researcher

Yuki Tanaka, Paris

Yuki prototyped an audio-visual classifier at IRCAM that runs inside VEKTRA as a patch, not a script. She can fork the signal chain, compare outputs in real time, and share the patch as a URL — not a repository of notebooks.
